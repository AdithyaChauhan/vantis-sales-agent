# Prompts

Every LLM prompt lives here as a `.md` file. Code loads them with `load_prompt(name)` (`backend/app/core/prompts.py`); no prompt text is written in code. Each file holds only the prompt text.

| File | Used by | Purpose |
|---|---|---|
| `system_prompt.md` | The agent node (`app/agent/graph.py`), as the system message | Role, tone, KB-only rule, citation rule, at most one follow-up question, the never-invent list (KB Section 16), off-topic redirect, KB and user text treated as data. T8a: tool policy (`search_knowledge_base`, `check_service_area`), how to word listed and unverified cities, list every offering, short replies, no claimed actions. T8b: the four lead tools, contact requests first, one question for up to two details, city confirmation, gentle next step, never a score or status. T10b: plain words (no copied KB text or office terms), numbered lists, each KB section cited once with its full label and never a tool, an offer after information questions and details only after interest, unlisted cities explained once in its own words |
| `lead_qualification_prompt.md` | `app/leads/reason.py`, sent to the fast model | Writes the one-sentence `reason` for a lead's status from the score breakdown only (status, score, rule labels with points, caps, city). It never sees a name, phone, email or money amount. It must not mention prices, savings, subsidies, financing, EMIs, guarantees or dates (KB Section 16). Code checks the reply and uses a template sentence when it is empty, too long, more than one sentence, names another status or touches a forbidden topic. Placeholders: `{status}`, `{score}`, `{city}`, `{factors}`, `{caps}` |
| `rag_prompt.md` | The agent node, wrapping the customer's latest message | Shows the retrieved chunks inside `<context>`, each starting with its label `[KB Section N: Title]`; sets the citation format; says what to do when the context does not cover the question. T8b: the `<lead_progress>` block (built in code: field names and what is still needed, never personal values, never a score; T10b: says not to ask for details while the customer has only asked for information). T10b: each KB section cited once, never a tool. Placeholders: `{context}`, `{lead_progress}`, `{question}` (filled with `str.replace`, the customer's text last) |
| `lead_extraction_prompt.md` | The understand node (`app/agent/understand.py`), sent with structured output to `understand_llm` (T10b: the main model, then fast, then Groq, each cut off after 5 s) | Intents (question, buying interest, greeting, reply to the assistant, thanks or bye, existing-customer issue, off-topic), a standalone `search_query` in the KB's own words, and the lead details the customer stated (`LeadData` field names and descriptions). Gets the KB section titles and the KB Section 8 summary chunk from the database, and the last 6 messages. Placeholders: `{section_titles}`, `{catalog}`, `{history}`, `{message}` (filled last) |
